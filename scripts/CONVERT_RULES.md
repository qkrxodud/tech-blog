# 글 변환 규칙

소스 루트: `/Users/taeyoung/blog/Export-c1198803-3981-4e38-9804-6e391f86aed6/_tistory_ready/`
대상 루트: `/Users/taeyoung/blog/tech-blog/content/`

각 항목마다 소스 폴더의 `post.md`와 `meta.md`를 읽고 `content/<slug>/index.md`를 작성합니다.

## 출력 파일 형식

```
---
title: "제목"
tags: ["태그1", "태그2"]
summary: "한두 문장 요약"
---

본문...
```

## 규칙

1. **문체 통일(가장 중요)** — 본문 전체를 일관된 존댓말(…합니다/…입니다 체)로 다시 씁니다. 반말·평어체("정리했다", "~이다")를 모두 존댓말로 바꾸고, 이미 존댓말인 문장도 어투가 일관되도록 다듬습니다. 개조식 목록 항목(명사형 종결, 예: "제목을 50글자 내로 제한")은 그대로 두어도 됩니다.
2. **내용 보존** — 요약하거나 생략하지 마세요. 모든 문단, 헤딩, 코드 블록, 표, 링크, 인용을 유지합니다. **코드 블록 내부는 절대 수정하지 않습니다.**
3. **오탈자 교정** — 명백한 오탈자와 띄어쓰기 오류를 고칩니다(예: "갖으려고"→"가지려고", "관려"→"관련"). 기술 용어 오타도 교정합니다(예: "Transcation"→"@Transactional", "GarBage"→"Garbage", "cuncurrency"→"concurrency", "Architecure"→"Architecture", "FokeJoin"→"ForkJoin").
4. **title** — `meta.md`의 제목을 기반으로 하되 오타를 고치고 자연스럽게 정리합니다. `[클릭]` 같은 클릭 유도 문구와 `01.`, `05` 같은 번호 접두어는 제거합니다(시리즈 순서는 별도 관리됩니다). `[도메인 주도 개발 시작하기] - 애그리거트`처럼 접두어 뒤에 하이픈이 붙은 형태는 `[도메인 주도 개발 시작하기] 애그리거트`로 정리합니다.
5. **tags** — `meta.md`의 "추천 태그"를 사용합니다 (3~6개).
6. **summary** — 글 내용을 바탕으로 목록에 노출될 1~2문장 소개를 존댓말로 새로 작성합니다 (60~120자, 낚시성 없이 내용을 정확히 설명).
7. **이미지 복원** — `post.md`에는 로컬 이미지 링크가 제거되어 있습니다. `meta.md`의 `## 이미지` 표(파일명 + 본문 위치 설명)를 보고 해당 위치에 `![](images/파일명)` 형태로 삽입합니다. **파일명의 공백은 하이픈으로 바꿔야 합니다** (예: `02_image 1.png` → `images/02_image-1.png`). 실제 파일은 `content/<slug>/images/`에 이미 복사되어 있으니 `ls`로 정확한 파일명을 확인하세요. 외부 URL 이미지(`https://...`)는 `post.md`에 이미 들어 있으므로 그대로 둡니다.
8. **정리** — 본문에 H1(`# 제목`) 줄이 남아 있으면 제거합니다(제목은 frontmatter로만). 노션 잔여물(notion.so 링크 등)은 제거하거나 문맥에 맞게 처리합니다. `meta.md`에 "발행 시 `###` 승격 고려" 같은 제안이 있으면 반영해도 좋습니다.
9. **frontmatter 형식** — 문자열은 반드시 큰따옴표로 감싸고, 내부 큰따옴표는 `\"`로 이스케이프합니다. `summary`는 반드시 한 줄이어야 합니다.

폴더명에 대괄호·쉼표 등 특수문자가 있으니 셸에서 다룰 때는 따옴표로 감싸세요.
